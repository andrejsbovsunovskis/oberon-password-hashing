# Запись о переносимости

[English version](portability.md)

Слова SHA-256 представлены 32-битными битовыми шаблонами `INTEGER`. Сложение переводит операнды в ограниченную 64-битную арифметику `SYSTEM.INT64`, выполняет сокращение по модулю `2^32` и возвращает результат без signed overflow `INTEGER`. XOR, AND, NOT, вращения, сдвиги, декодирование входа и кодирование дайджеста используют определённые битовые операции `SYSTEM` Ofront+; порядок байтов задаётся явно и не зависит от CPU. Криптографические октеты используют 8-битный `SYSTEM.CHAR8` FreeOberon, а не 16-битный `CHAR`.

Код опирается на то, что Ofront+ с `-88` предоставляет 32-битный two's-complement `INTEGER`, 64-битный `SYSTEM.INT64`, 8-битный `SYSTEM.CHAR8`, с преобразованиями `ORD` и `SYSTEM.VAL` в диапазоне `0..255`, и операции `SET` над битовыми шаблонами `INTEGER`. `scripts/test.sh` оставляет включёнными проверки границ, типов, assertions и указателей Ofront+. Тесты проверяют переносы слов, вращения, логические сдвиги, стандартные SHA-векторы, fixtures HMAC/PBKDF2, границы API и 100 000 мутаций парсера.

`SecureRandom` использует файловый API `Platform` FreeOberon для чтения `/dev/urandom` на macOS и Linux. Неполное чтение, ошибки и полностью нулевой результат отклоняются; псевдослучайного fallback нет.

Штатный `fob` выбирает Oberon-07 и широкие символы (`-7w`): `CHAR` имеет размер 2 байта, `LONGINT` — 4 байта. Поэтому для криптографических буферов нужен именно `SYSTEM.CHAR8`, а для промежуточного сложения — `SYSTEM.INT64` с преобразованиями `SYSTEM.LONG`/`SYSTEM.SHORT`. `TestDialect` проверяет эти размеры, все значения октетов `0..255`, перенос сложения и сохранность входного массива.

Параметры массивов и записей без `VAR` в этом режиме Ofront+ передаются по ссылке только для чтения. Они заменяют Component Pascal `IN` без копирования секретных входов и по-прежнему принимают строковые литералы. Функции имеют единственный завершающий `RETURN`; процедуры без результата используют условное выполнение вместо раннего `RETURN`.
